# MusicFree 0.6.2 Fork 开发计划

## 项目概述
在 MusicFree `v0.6.2` 基础上为个人 fork 增加播放换源、插件健康管理和下载结果查看能力。关键约束：一个需求一个分支、不推回原作者仓库、Android 优先、第一版不新增外部依赖、文档与代码改动分离审查。

## 功能需求
- R1：播放失败自动切换其他可用音源，覆盖取源失败与底层播放失败。
- R2：自建歌单继承全局换源能力；不做歌单级独立配置。
- R3：插件健康与生命周期管理，包括临时不可用、手动失效、归档和分组。
- R4：下载结果历史，至少可查看最近 10 条成功 / 失败记录。
- R5：插件订阅关系、重复插件防抖、插件管理页采用分区页优化信息架构。
- R6：插件启动加载与播放状态恢复优化，元数据先行、代码按需挂载，并治理被动恢复引发的取源和歌词搜索。

## 非目标
- 不向原作者仓库提交 PR。
- 第一版不做 iOS 验收。
- 第一版不做下载系统通知。
- 第一版不新增通知、下载队列、数据库等外部依赖。
- 第一版不实现下载失败记录的手动 / 自动重试。
- 第一版不把插件健康、换源缓存、下载历史纳入备份。
- 不尝试合并或执行不可信插件代码；插件“合并”只做逻辑分组与状态管理。
- 不按歌单单独配置换源策略。

## 技术决策
- 语言/版本：TypeScript，项目当前依赖 TypeScript `^5.3.3`。
- 框架/库：React Native `0.76.5`、React `18.3.1`、react-native-track-player `^4.1.1`。
- 存储：继续使用 MMKV；换源缓存、插件健康、下载历史使用独立 MMKV store 或明确的 key namespace。
- 外部依赖上限：功能实现阶段新增运行时依赖为 0。
- 平台：Android 优先；验收使用 Android 真机。
- 基线：`v0.6.2 = b3cb5e5829dc600af86731c582429f5eb99cad27`。
- 分支规则：一个需求一个分支；功能完成后验证、review、测试，再提交并等待用户确认。

## 模块划分
- `TrackPlayer`：负责播放队列、播放错误事件和最终应用换源结果；不直接枚举全部插件。
- `MediaSourceResolver`：负责候选插件选择、严格匹配、失败候选去重、超时控制和结果缓存。
- `PluginManager`：负责插件安装、更新、排序、启用状态；后续增加健康状态与订阅来源。
- `PluginHealth`：负责连续失败计数、临时不可用、手动失效、归档和启动恢复。
- `DownloadHistory`：负责下载成功 / 失败结果持久化与最近 10 条裁剪。
- UI 层：只读取 service 状态并触发动作，不直接写 MMKV 业务数据。

## 下一阶段预告

### 阶段 1：R3 插件健康与生命周期  ✅
**目标**：建立插件 `available / quarantined / userInvalid / archived` 状态，使连续失败 5 次的插件在本次会话中退出搜索和换源候选，并在下次启动自动恢复 `quarantined`。

**关键验收**：
- 连续 5 次插件级失败后自动临时不可用。
- 全局网络错误不误标插件失效。
- 手动状态不自动恢复。
- 搜索和后续换源候选遵守插件状态。
- 插件管理页可见状态并可手动恢复。

**完成记录**：

- 已实现 `available / quarantined / userInvalid / archived` 状态。
- 已接入搜索和能力插件过滤。
- 已在插件管理页展示状态和恢复操作。
- 功能提交：`feat(plugin): add plugin health lifecycle`。

---

### 阶段 2：R1/R2 播放失败换源  ✅
**目标**：集中处理取源失败与底层播放失败，按插件顺序尝试严格匹配候选，并缓存成功换源结果。

**关键验收**：
- 取源失败和底层播放失败都进入同一换源会话。
- 最多尝试 5 个可用候选，总预算 15 秒。
- 候选使用现有插件顺序；配置的替代插件优先。
- 标题、艺人规范化后一致，duration 差值不超过 3 秒。
- 禁用、临时不可用、手动失效、归档插件不参与候选。
- 换源成功不改写原始歌曲身份，自建歌单自然继承全局策略。
- 换源结果可清理，不进入备份。

**完成记录**：

- 已新增 `MediaSourceFallbackResolver`。
- 已接入取源失败与 `Event.PlaybackError` 后续重试。
- 已移除旧的模糊编辑距离兜底。
- 已提供严格匹配开关、总开关和缓存清理入口。
- 功能提交：`feat(player): add play source fallback`。

---

### 阶段 3：R5 插件订阅与防重复  ✅
**目标**：建立稳定订阅 ID 与插件来源映射，串行化订阅更新，重构插件管理页分区，并识别同名 / 同来源插件。

**已实现**：

- 插件管理页已分为概览、已安装插件、订阅管理、插件排序和维护操作。
- 订阅管理保留一级页面，展示稳定 ID、URL、最近更新时间和插件数量。
- 订阅 URL 生成基于内容的稳定 ID；插件安装成功后记录插件 hash、名称、订阅、来源 URL、版本和时间。
- 所有 URL / 本地插件安装进入串行队列；订阅更新整体也进入独立串行队列。
- 相同 `plugin.name` 分组展示；改用不同名称但 `srcUrl` 相同的插件标记为疑似重复音源，默认归档新来源。
- 订阅内低版本内容记录为重复归档映射，不替换已安装的更高版本。
- 订阅中消失的插件只标记“订阅中已不存在 / 可清理”，不自动删除。
- 删除订阅固定删除关联插件，并同步清理订阅配置；共享来源的插件不会被误删。
- 订阅详情支持编辑、复制、单独更新和只读插件列表。
- 换源 duration 做秒 / 毫秒归一化；目标 duration 缺失时改由文本严格匹配兜底。
- 修复订阅删除弹窗被父弹窗立即覆盖的问题。
- 带操作按钮的 Toast 默认展示 6 秒。
- 删除订阅固定同时清理配置与关联插件；订阅入口直达详情，维护操作默认折叠。
- 概览只展示统计，订阅分区首行提供添加订阅。

**收尾记录**：

- 功能提交：`feat(plugin): add subscription source management`；另有三轮真机反馈修复。
- 已完成订阅详情、单独更新、删除配置残留、概览统计和维护折叠。
- 最终 Android 回归统一放入阶段 6，不在本阶段继续扩展。

### 阶段 4：R4 下载结果历史  🚧
**目标**：持久化最近 10 条下载成功 / 失败结果，并支持查看与清理。

**关键验收**：
- 成功 / 失败结果可在重启后查看。
- 全部状态合计保留最近 10 条。
- 支持按成功 / 失败筛选和清理历史。
- 失败记录展示原因，但不做手动 / 自动重试。
- 不新增通知依赖；历史不进入备份 / 恢复。
- 不影响下载完成后的本地音乐入库逻辑。

**分支**：`feat/0.6.2-download-history`（基于 R5 收尾分支创建）。

### 后续预告：R6 插件启动加载与播放状态恢复优化

R6 排在 R3 -> R1/R2 -> R5 -> R4 之后实施。范围、验收和风险见 `docs/fork-requirements.md` 的 R6 章节。
